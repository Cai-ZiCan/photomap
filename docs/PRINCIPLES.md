# 工作原则与设计原则

> 本文档是「摄影地图」项目的最高约定：功能取舍、实现方式与交互细节发生分歧时，回到这里裁决。

## 一、产品定位

公开的 WebGIS 摄影观赏点位地图（赏花 / 秋叶 / 雪景 / 星空等专题），网页即开即用，交互对标 Google Earth / 百度地图。三类信息来源：

1. **制作者上传**（核心、可信度最高）
2. **访客投稿**（必审后发布）
3. **程序抓取 + AI 提取**（辅助，粘贴链接/文本，产出草稿进审核队列）

## 二、工作原则

1. **增量交付**：每个里程碑结束都是可运行、可演示的状态；不为了"先搭个完美架子"而长期不可运行。
2. **数据可携**：点位、专题、照片可一键导出（JSON + 图片包），不锁定在任何服务上；坐标统一以 **WGS-84** 存储，换底图、换数据库、换部署都不丢数据。
3. **主链路独立**：手工上传是主链路。AI、抓取、地图瓦片属于增强与依赖，**任何一个外部服务失效（AI 未配 key、目标网站改版、高德瓦片变动），主链路必须照常工作**。
4. **内容合规**：
   - 所有内容强制标注来源（制作者 / 网友投稿 / 网络采集 + 原文链接）；
   - 投稿必审后发布；上传限制类型与大小；仅收集必要信息（联系方式选填、仅限邮箱，仅管理员可见）；
   - 采集仅针对允许公开获取的页面，遵守目标平台条款。
5. **移动端同源适配**：桌面右侧详情栏 / 移动端底部抽屉，同一套代码同一份数据。
6. **国内优先，处处可配置**：底图、AI 服务商、站点信息全部做成配置项，默认选国内可达方案（高德免 key 瓦片、智谱 AI），但可随时切换。
7. **简单优先**：单管理员、单机单库（SQLite + 本地文件照片）；不引入账号体系、不引入消息队列，复杂度只在被需要时引入。

## 三、设计原则（交互与视觉）

1. **经典 GIS 交互**：缩放、比例尺、图层切换（标准/卫星/OSM）、全屏、回位按钮 —— 与百度/高德地图的使用习惯一致，不自创操作。
2. **点位符号**：按专题配色的经典地图 pin；数量多时自动聚合并按主要专题着色；选中态放大。
3. **悬停即预览**：Tooltip = 代表图缩略图 + 点位名 + 专题标签；触摸设备跳过悬停，直接点击。
4. **点击看详情**：右侧滑出详情栏（移动端为底部抽屉）：图集、专题标签、最佳观赏月份条、介绍、地址与小贴士、来源标注、一键导航（高德/百度）、复制坐标、分享深链 `/spot/:id`。
5. **可分享的状态**：专题/月份/关键词过滤同步到 URL；每个点位有独立深链。
6. **以图为主**：照片是主角，界面克制；点位着色来自专题色，不用装饰性颜色。
7. **空态与失败态说人话**：AI 未配置、抓取失败、网络错误都给出「下一步怎么办」的提示，不甩错误码。

## 四、技术约定

| 项 | 约定 |
|---|---|
| 坐标 | 存储/导出一律 WGS-84；渲染高德底图时前端做 GCJ-02 转换，选点时反算回 WGS-84 |
| 数据库 | node:sqlite（Node 24 内置，零原生依赖）；单文件 `data/photo-map.db` |
| 照片 | 上传即转 WebP（原图 ≤1600px + 480px 缩略图），存 `data/uploads/`，DB 存相对路径 |
| 认证 | 单管理员密码（scrypt 存储）+ HMAC 签名 Cookie；投稿接口限流 + 蜜罐字段 |
| API | REST + JSON；公开点位接口返回 GeoJSON，后续小程序直接复用 |
| 前端 | Vite + Vue 3 + TS + OpenLayers（ESM 按需引入），无重型 UI 框架 |
