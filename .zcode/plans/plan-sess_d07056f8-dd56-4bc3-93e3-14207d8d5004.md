# 摄影地图 · 实施计划

## 一、产品定位（本期范围）
- 公开 WebGIS 网页（浏览器直接访问，无需安装），展示摄影观赏点位，支持赏花、秋叶等多主题专题。
- 三类信息来源：**制作者上传（核心）**、**访客投稿（审核后发布）**、**粘贴链接/文本 → 程序抓取 + AI 提取（辅助）**。
- 交互对标 Google Earth / 百度地图：经典地图控件、点位符号、悬停缩略图提示、点击弹出详情侧栏。
- **本期不做**：微信小程序（但 API 与前端解耦，后续小程序直接复用 API）、定向平台批量爬取（小红书/微博等，风控高，留作后续适配器）、用户账号体系（投稿为游客模式 + 联系方式）。

## 二、工作原则（写入 docs/PRINCIPLES.md）
1. **增量交付**：每个里程碑结束都是可运行、可演示的状态。
2. **数据可携**：点位/图片可一键导出（JSON + 图片包），不锁定在任何服务上；坐标统一存 WGS-84。
3. **主链路独立**：手工上传为核心链路；AI/抓取仅为增强，任何外部依赖（AI key、目标网站）失效都不影响主链路。
4. **内容合规**：所有内容标注来源与作者；投稿必审后发布；上传限制类型/大小；仅收集必要信息。
5. **移动端同源适配**：桌面右侧详情栏 / 移动端底部抽屉，同一套代码。
6. **国内优先**：底图、部署、AI 服务商默认选择国内可达方案，全部做成可配置。

## 三、设计原则
- 经典 GIS 控件：缩放、比例尺、图层切换（标准/卫星/OSM）、全屏、回位。
- 点位：按专题配色的经典圆形 pin；数量多时自动聚合（OpenLayers 内置 `Cluster` 源，聚合圆按主要专题着色）。
- 悬停：共享 Overlay + `forEachFeatureAtPixel` 命中检测实现「代表图缩略图 + 点位名」Tooltip（触摸设备跳过，直接点击）。
- 点击：右侧滑出详情栏 —— 图集、名称、专题标签、最佳观赏月份条、介绍、地址/小贴士、来源标注、导航按钮（跳高德/百度地图）、复制坐标、分享深链 `/spot/:id`。
- 过滤与查找：专题 chips 多选过滤、最佳月份过滤、关键词搜索，状态同步到 URL 可分享。

## 四、技术方案（地图库按你的倾向改为 OpenLayers）
| 项 | 选型 | 理由 |
|---|---|---|
| 前端 | Vite + Vue 3 + TypeScript + **OpenLayers（最新稳定版，ESM 按需引入）** | 底图接入更全：XYZ/WMTS/自定义 tileGrid/重投影（CGCS2000）、`tileLoadFunction` 瓦片失败重试兜底（对免 key 社区瓦片源是实打实的稳定性收益）、内置聚合、动态样式强、未来矢量瓦片无需换库。体积代价（gzip 约为 Leaflet 3–5 倍）在瓦片主导的地图页可接受，配合 gzip/缓存/管理端路由懒加载控制首屏 |
| 后端 | Node 24（本机已有 v24.16.0）+ Express + **内置 node:sqlite** | 零原生依赖，Windows 免编译问题；单文件数据库易备份 |
| 图片 | multer 接收 + sharp 压缩转 WebP，存 `data/uploads/` | 控制体积，DB 存相对路径 |
| AI | OpenAI 兼容接口，`.env` 配 AI_BASE_URL / AI_API_KEY / AI_TEXT_MODEL / AI_VISION_MODEL（默认指向智谱开放平台，可换任意兼容服务） | 未配 key 时仅 AI 功能不可用，其余全部正常 |
| 底图 | 默认高德栅格瓦片（免 key、国内快），渲染时自动做 GCJ-02↔WGS-84 坐标转换；可切换卫星图、天地图（免费 key）、OSM | 存储统一 WGS-84，切底图不错位 |
| 会话/安全 | 管理员密码（首次启动设置）+ 签名 Cookie；投稿接口限流 + honeypot 字段；上传白名单校验 | 单管理员场景，够用且简单 |
| 运行 | server 同进程托管 API 与前端构建产物，端口 8787；开发时 Vite 5173 代理 | 一条命令起服务，天然可部署 |

## 五、数据模型
- `spots`：name / description / lat / lng / address / region / tips / months(JSON 最佳月份) / status(pending|published|rejected|archived) / source(creator|user|crawler) / source_url / submitter_name / submitter_contact / review_note / featured_photo / 时间戳
- `themes`：slug / name / color / icon / description / sort（管理员可增删改）
- `spot_themes`：点位↔专题多对多
- `photos`：spot_id / path / caption / credit / sort
- `settings`：管理员密码哈希、站点配置
- 种子数据：预置 8–12 个示例点位（含本地生成的占位图），管理端提供「清空示例数据」。

## 六、API 概要
- 公开：`GET /api/themes`、`GET /api/spots`（GeoJSON，支持 theme/bbox/q/months 过滤）、`GET /api/spots/:id`、`POST /api/submissions`（投稿，multipart 图片）
- 管理（会话保护）：登录/登出/首次设置密码；点位 CRUD + 图片上传/排序/设封面；专题 CRUD；审核队列（通过/拒绝/附言）；`POST /api/admin/ai-extract`（URL 或文本 → 抓取+AI → 草稿进审核队列）；`GET /api/admin/export`（JSON+图片打包）

## 八、实施里程碑（每步落盘即可运行）
- **M0 初始化**：git init、.gitignore、README + 三份 docs（原则/架构/部署）、安装依赖。← 你要求的「先初始化、明确工作原则设计原则」
- **M1 后端与数据**：建表迁移、种子示例、公开 API、图片上传压缩。
- **M2 地图前端 MVP**：OpenLayers 地图与全部交互落地（Tooltip/侧栏/聚合/专题与月份过滤/搜索/底图切换含卫星/移动端抽屉）。
- **M3 管理端**：登录、点位 CRUD（地图选点，含 GCJ-02 反算）、照片管理、专题管理、一键导出。
- **M4 投稿与审核闭环**：公开投稿表单（限流+honeypot）→ 审核队列 → 发布/拒绝。
- **M5 链接导入 + AI**：粘贴 URL（公众号文章/博客/旅游网页）或文本 → 抓取正文图片 → AI 提取结构化草稿 → 审核队列；未配 key 时给出清晰提示并优雅降级。
- **M6 打磨与部署**：空态/异常处理、性能（首屏体积、图片懒加载、瓦片重试）、Dockerfile + DEPLOY.md 验证。

## 九、验证方式
- 每个里程碑 `npm run dev` 起服务，用浏览器自动化自测关键交互（悬停提示、点击侧栏、过滤、投稿→审核→发布全流程、链接导入）并截图确认。
- 最终 `npm run build && npm start` 生产模式回归；导出/导入数据回归。

## 十、已知风险
- 高德免 key 瓦片属社区用法，理论上可能变动 → 底图做成配置项 + OL tileLoadFunction 重试兜底，可随时切天地图/OSM。
- 抓取依赖目标页面结构，复杂页面由 AI 兜底解析；个别站点（强登录墙）无法抓取属预期，转手工上传。
- OL 包体大于 Leaflet → 按需引入 + 生产压缩 + 管理端懒加载控制。
- 照片版权由制作者审核把关，系统负责强制标注来源。
